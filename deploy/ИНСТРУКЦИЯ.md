# Инструкция: сайт и сервер Новокузнецкого ВГСО

Документ для администратора сайта и для того, кто обслуживает сервер.
Все команды выполняются в Терминале Ubuntu на этой машине.

---

## 1. Быстрый старт

| Что | Где |
|---|---|
| Сайт | **https://nvgso.ru** |
| Админка | **https://nvgso.ru/wp-admin/** |
| Логин | `admin` |
| Пароль | в файле `~/nvgso-access.txt` |
| 2FA | QR-код `~/nvgso-2fa-qr.png`, секрет и резервные коды — в `~/nvgso-access.txt` |
| E-mail администратора | `prognvgso@vgsch.ru` |
| Инструкция | `/home/nvgso/ИНСТРУКЦИЯ.md` (ярлык) |
| Тема | `wp-content/themes/nvgso` |
| Резервные копии | `/var/backups/nvgso` |

Порядок входа:

1. Откройте `https://nvgso.ru/wp-admin/`.
2. Введите логин `admin` и пароль из `~/nvgso-access.txt`.
3. Введите шестизначный код из приложения-аутентификатора
   (Google Authenticator, Aegis, 1Password и т.п.), куда вы добавили
   секрет по QR-коду `~/nvgso-2fa-qr.png`.

> Если код не подходит, используйте один из резервных кодов из
> `~/nvgso-access.txt` (каждый код одноразовый).

## 3. Доступы и безопасность

### 3.1. Где лежат доступы

- `~/nvgso-access.txt` — пароль WordPress, 2FA, БД (права 600);
- `/root/nvgso/secrets.env` — те же данные для root;
- `~/nvgso-2fa-qr.png` — QR-код для добавления в аутентификатор.

### 3.2. Сменить пароль WordPress

Админка: **Пользователи → Профиль → Новый пароль**.
Или:

```bash
sudo -u www-data wp --path=/var/www/nvgso user update admin --user_pass='НОВЫЙ_ПАРОЛЬ'
```

После смены обновите `~/nvgso-access.txt`.

### 3.3. Двухфакторная аутентификация

2FA включена через Wordfence для роли «Администратор». Настроена для `admin`:
секрет, QR-код и 10 резервных кодов.

Если потеряли телефон:

1. Используйте резервный код (каждый одноразовый).
2. Если коды закончились — удалите 2FA для пользователя:

```bash
sudo mariadb nvgso_wp -e "DELETE FROM wp_wfls_2fa_secrets WHERE user_id=1;"
```

3. Войдите по паролю и заново настройте 2FA:
   **Wordfence → Login Security → 2FA**.

Не отключайте 2FA «на всякий случай»: это требование безопасности.

### 3.4. Создать редактора

**Пользователи → Добавить нового**, роль «Редактор».
Для редакторов рекомендуется включить 2FA в Wordfence.

### 3.5. Почта сайта

В WP Mail SMTP уже указаны сервер и получатель:

- SMTP: `smtp.armgs.team`, порт `465`, шифрование **SSL**;
- логин: `e.zenchenko@vgsch.mchs.gov.ru`;
- получатель обращений: `e.zenchenko@vgsch.mchs.gov.ru`;
- IMAP (только для чтения почты, форме не нужен): `imap.armgs.team:993`, TLS.

Сервер принимает **только пароль приложения** (application password).
Обычный пароль ящика отклоняется с ошибкой:

```
535 5.7.0 NEOBHODIM parol prilozheniya / Application password is REQUIRED
```

Создайте пароль приложения в настройках безопасности почтового ящика
(веб-почта `armgs.team`), затем вставьте его в
**Настройки → WP Mail SMTP → SMTP → Пароль** и отправьте тестовое письмо.

Пока пароль приложения не указан:

- письма не отправляются;
- обращения с формы сохраняются в админке: **Обращения**;
- пароль администратора можно сменить командой (раздел 3.2).

Форма проверена: тестовое обращение успешно сохраняется в «Обращения».
После настройки SMTP проверьте доставку тестовым письмом.

### 3.6. Ограничить /wp-admin по IP

Если сайт станет публичным, можно добавить в Nginx:

```nginx
location ^~ /wp-admin/ {
    allow ВАШ_IP;
    allow 10.0.2.0/24;
    deny all;
    # остальные директивы — как в основном location
}
```

Не включайте, пока не убедитесь, что ваш IP входит в `allow`.

## 4. Как работать с сайтом

### 4.1. Настройки сайта

**Настройки → Сайт NVGSO** — единая форма:

- название организации, адрес, телефоны, e-mail, режим работы;
- заголовок и подзаголовок главной;
- текст «О филиале»;
- четыре показателя на главной;
- ссылки на сайты ФГУП «ВГСЧ» и МЧС России.

После сохранения проверьте главную и контакты.

### 4.2. Главная страница

Главная — статическая страница `Главная` (template `front-page.php`).
Она собирается автоматически из:

- настроек (раздел 4.1);
- последних новостей;
- документов;
- подразделений;
- медиатеки (фотоблок).

Чтобы изменить блоки — правьте настройки или соответствующие записи.
HTML главной вручную не редактируется.

### 4.3. Новости

**Записи → Добавить запись.**

- заголовок, текст, краткое описание (цитата);
- рубрика (Учения, Профилактика, Награждения, Юбилеи, Память, События);
- избранное изображение — из медиатеки;
- дата.

Список новостей — страница `Новости` (`/news/`), она выбрана как
страница записей в **Настройки → Чтение**. Фильтр по рубрикам работает
через ссылки.

### 4.4. Документы

**Документы → Добавить документ.**

- заголовок;
- категория (`doc_category`);
- в метабоксе **«Файл и реквизиты документа»** нажмите «Выбрать файл»
  и выберите PDF из медиатеки;
- там же заполняются дата документа, количество страниц и примечание.

Страница `/documents/` выводит документы с фильтром по категориям.

### 4.5. Фотогалерея

**Фотогалерея → Добавить фотоматериал.**

- заголовок, подпись;
- в метабоксе **«Изображение и подпись»** выберите изображение
  из медиатеки;
- альбом (`album`): «Учения и обмен опытом», «Память и торжества»,
  «Награждения»;
- дата, тип (фото/видео), ссылка на видео для видеоматериалов.

Страница `/gallery/` выводит сетку с лайтбоксом и фильтром по альбомам.

### 4.6. Структура и командование

- **Подразделения** — взводы, штаб, адреса, телефоны, состав
  (метабокс «Данные подразделения»).
- **Командование** — должность (заголовок), ФИО, звание, телефон,
  приём (метабокс «Данные сотрудника»).

Эти данные выводятся на страницах «Структура», «Об отряде», «Контакты».
Замените `[ФИО]` на реальные данные.

### 4.7. Телефонный справочник

Хранится в опции `nvgso_phones` (импортирован из прототипа).
Редактируется через WP-CLI или через настройку темы; для массового
обновления удобно:

```bash
sudo -u www-data wp --path=/var/www/nvgso option get nvgso_phones --format=json
```

Телефоны `00-00-00` — демонстрационные, замените на реальные.

### 4.8. Правовые страницы

Страницы «Политика обработки ПДн», «Политика компании», «Политика cookie»
используют шаблон **«Правовая страница»**:
контент + автоматическое оглавление по заголовкам `h2` с `id`.

Редактируются как обычные страницы. Тексты подлежат утверждению
Заказчиком.

### 4.9. Медиатека

**Медиатека → Добавить новый.** Ограничение — 64 МБ на файл.
Форматы: WebP, JPEG, PNG, PDF.

- имена файлов — латиницей, без пробелов;
- заполняйте alt-текст;
- изображения до 2000 px по длинной стороне;
- EWWW Image Optimizer включён.

Массовый импорт через WP-CLI: файл должен быть доступен `www-data`,
поэтому копируйте в `/tmp`:

```bash
cp foto.webp /tmp/foto.webp && chmod 644 /tmp/foto.webp
sudo -u www-data wp --path=/var/www/nvgso media import /tmp/foto.webp --title='Подпись'
```

### 4.10. Заменить демо-данные

Обязательно перед публикацией:

1. **Настройки → Сайт NVGSO** — телефоны `+7 (3843) 00-00-00`,
   `00-00-01`, e-mail.
2. **Командование** — ФИО `[ФИО]`, звания, телефоны.
3. **Подразделения** — адреса и телефоны.
4. **Телефонный справочник** — опция `nvgso_phones`.
5. Проверить тексты новостей и документов: в прототипе они
   демонстрационные.

В админке показывается предупреждение, пока телефоны `00-00-00` или
ФИО `[ФИО]` не заменены.

### 4.11. Кэш

Включён WP Super Cache (простой режим). При сохранении записи кэш
чистится автоматически. Если изменения не видны:

```bash
sudo -u www-data wp --path=/var/www/nvgso eval 'wp_cache_clear_cache();'
```

или **Настройки → WP Super Cache → Delete Cache**.

### 4.12. Меню

Шапка и подвал темы построены по структуре прототипа:
Главная · О филиале (Об отряде, Структура, Деятельность, Ветеранам) ·
Пресс-центр (Новости, Фотогалерея, Документы) · Контакты.

Пункты меню заданы в `header.php` темы. Если нужно изменить состав —
отредактируйте `deploy/theme-src/header.php` и выложите тему (раздел 12)
или обратитесь к разработчику.

### 4.14. Командование отряда

Данные карточек «Руководство отряда» на странице «О филиале» заполняются в
одной форме:

**Настройки → Командование**

или

**Командование → Форма заполнения**

В таблице перечислены все должности. Для каждой строки заполняются:

- должность (заголовок);
- ФИО;
- звание / должность по штату;
- телефон;
- приём / режим;
- e-mail;
- порядок (0 — командир отряда, 1 — заместитель и т. д.).

Пустая строка внизу добавляет нового сотрудника. После заполнения нажмите
«Сохранить». Страницу «О филиале» редактировать не нужно — блок строится из
этих записей.

Контакты приёмной внизу блока (телефон и e-mail) задаются отдельно:
**Настройки → Сайт NVGSO**, поля «Телефон приёмной» и «E-mail».

### 4.13. Вложения в форме обратной связи

Форма на странице «Контакты» принимает **один файл**:

- только **PDF** или **DOCX**;
- размер — **не больше 15 МБ**;
- вложение необязательно.

Проверка выполняется и в браузере, и на сервере. Файлы сохраняются в
`wp-content/uploads/nvgso-feedback/`, прямой доступ к этой папке закрыт в
Nginx (403). Скачать вложение можно из карточки обращения в админке —
раздел **«Обращения»**, кнопка «Скачать». При настроенном SMTP файл
уходит вложением вместе с письмом.

Если файл не PDF/DOCX или больше 15 МБ, форма покажет ошибку и не создаст
обращение. DOCX с макросами отклоняется. До отправки браузер показывает имя
и размер выбранного файла.

**Антивирус.** Вложение проверяется ClamAV 1.5.4 (базы в `/var/lib/clamav`).
Заражённый файл отклоняется, в обращение и письмо он не попадает. Если
антивирус недоступен, вложение не принимается — форма сообщит об ошибке.
Базы обновляются ежедневно в 04:17 скриптом
`/usr/local/bin/nvgso-clamav-update.sh` с зеркала `https://clamav-mirror.ru/`
(журнал `/var/log/nvgso-clamav-update.log`).

**Ограничение частоты.** С одного IP принимается не больше **5 обращений в
час**, и не чаще одного в **20 секунд**. При превышении форма показывает
сообщение «Слишком много обращений».

### 4.15. Зона ответственности

Список предприятий редактируется в отдельной форме:

**Настройки → Зона ответственности**

В таблице можно менять название и примечание, добавлять и удалять
предприятия, менять порядок стрелками ↑/↓ и сохранять одной кнопкой.
Над таблицей есть поля **«Надзаголовок»**, **«Заголовок»** и
**«Подзаголовок»** — они меняют текст шапки этого блока.
После сохранения карточки на странице «Об отряде» обновляются сразу.

### 4.16. Документы

Добавлять и редактировать документы удобнее всего в одной таблице:

**Документы → Форма документов**

или

**Настройки → Документы**

В таблице для каждого документа указаны: название, порядок, категория, дата,
количество страниц, примечание, PDF-файл и признак «Опубликован».
Новый документ добавляется через пустую строку внизу. PDF загружается в
медиатеку; при замене выберите новый файл.

Колонка **«Порядок»** со стрелками ↑/↓ меняет порядок сразу: стрелка
сохраняет новый порядок и очищает кэш страницы «Документы». Новые
документы добавляются в конец списка.

Если снять «Опубликован», документ сохранится как черновик. Категории
редактируются в **Документы → Категории документов**.

Стандартный способ тоже работает: **Документы → Добавить документ**,
блок «Файл и реквизиты документа» и выбор категории справа.


### 4.17. Подвал сайта

Подвал редактируется в **Настройки → Сайт NVGSO → Подвал сайта**:

- **Имя сайта в подвале** — выводится в нижней строке;
- **ФИО ответственного** и **Должность** — строка «Ответственный за сайт»;
- **Ссылка на мессенджер MAX** — если заполнена, в подвале появляется
  кнопка с иконкой MAX; рядом с полем в админке есть превью иконки;
- **Ссылка на группу ВКонтакте** — кнопка «ВКонтакте» с иконкой VK
  рядом с MAX (по умолчанию `https://vk.ru/nvgso`);
- **Описание в подвале** — текст под полным названием организации;
- **Строка о фото и видеоматериалах** — можно оставить ссылку на лицензию.

Пустые ФИО, должность и ссылка MAX просто не выводятся.


### 4.18. Подразделения отряда

Все карточки блока «Подразделения отряда» на странице «Структура»
редактируются в одной форме:

**Подразделения → Форма подразделений**

или

**Настройки → Подразделения**

Для каждой строки доступны: название, тип (штаб/взвод), город, адрес,
телефон, состав/отделения, описание и признак «Опубликовано».
Новое подразделение добавляется пустой строкой внизу. Стрелки ↑/↓
меняют порядок сразу, новые записи добавляются в конец.

### 4.19. Статистика посещаемости

Статистика локальная, без внешних счётчиков:

- виджет **«Посещаемость сайта»** на главной странице админки;
- страница **Dashboard → Статистика сайта**;
- показываются просмотры за сегодня, 7 и 30 дней, уникальные посетители,
  график, популярные страницы и источники переходов.

Учитываются только посетители, согласившиеся на аналитические cookie.
IP-адреса не хранятся — только хеш. Данные хранятся 365 дней.

### 4.20. 404 и страница недоступности

- **404** — тема сайта: крупный номер, поиск, быстрые ссылки на разделы.
- **500/502/503/504** — статическая страница
  `/var/www/nvgso-error/50x.html`, которую отдаёт Nginx, даже если PHP
  не работает. Настроено через `error_page` в HTTPS-сервере.
  Проверка: остановить `php8.3-fpm`, открыть сайт — должна появиться
  страница «Сайт временно недоступен», затем запустить PHP обратно.

Если недоступен сам Nginx, показать страницу с этого же сервера нельзя —
браузер покажет ошибку соединения; нужен внешний мониторинг.

### 4.16. Порядок реагирования

**Настройки → Порядок реагирования**

Меняются надзаголовок, заголовок и подзаголовок блока, а также все шаги:
номер, название и описание. Шаги можно добавлять, удалять и менять
стрелками ↑/↓. После сохранения блок на странице «Структура» обновляется.

## 5. Cookie-согласие

Реализовано собственное решение (без стороннего плагина):

- баннер с кнопками **«Принять все»**, **«Только необходимые»**,
  **«Настроить»**;
- модальное окно с категориями: функциональные, аналитические,
  маркетинговые;
- согласие хранится в cookie `nvgso_consent` (180 дней);
- каждая запись согласия пишется в БД `wp_nvgso_consents`;
- журнал: **Настройки → Cookie-согласия**;
- экспорт CSV — кнопка на странице журнала;
- кнопка «Сбросить моё согласие» — для проверки баннера.

Что записывается: время, действие, категории, адрес страницы, версия
политики, **хеши** IP и User-Agent (не сами IP). Персональные данные
минимизированы.

Аналитические скрипты не загружаются до согласия. Если появится
Яндекс.Метрика, подключайте её так:

```html
<script type="text/plain" data-consent="analytics">
  // код Метрики
</script>
```

Скрипт активируется только после согласия на аналитические cookie.

> Юридическую формулировку баннера и политики должен проверить
> ответственный за обработку ПДн.

## 6. Резервное копирование

### 6.1. Ежедневно

В **02:30** cron запускает `/usr/local/bin/nvgso-backup.sh`:

- дамп БД → `/var/backups/nvgso/db/nvgso_wp_ГГГГ-ММ-ДД_ЧЧММ.sql.gz`;
- копия `wp-content/uploads` → `/var/backups/nvgso/uploads`;
- дампы старше 30 дней удаляются.

Лог: `/var/log/nvgso-backup.log`.
Ручной запуск:

```bash
sudo /usr/local/bin/nvgso-backup.sh
```

### 6.2. Выгрузка на NAS

Скрипт `/usr/local/bin/nvgso-nas-backup.sh` запускается в **03:00** и
копирует `/var/backups/nvgso` на ваш NAS по SSH.

1. Создайте конфиг:

```bash
sudo cp /etc/nvgso/nas-backup.conf.example /etc/nvgso/nas-backup.conf
sudo nano /etc/nvgso/nas-backup.conf
sudo chmod 600 /etc/nvgso/nas-backup.conf
```

2. Заполните `NAS_HOST`, `NAS_USER`, `NAS_PATH`.
3. Положите SSH-ключ в `/root/.ssh/nvgso_nas` (права 600) и добавьте
   открытый ключ на NAS.
4. Проверьте:

```bash
sudo /usr/local/bin/nvgso-nas-backup.sh
sudo tail -5 /var/log/nvgso-nas-backup.log
```

Пока конфиг не заполнен, скрипт пишет «NAS не настроен» и не падает.

### 6.3. Проверка восстановления

1-го числа в **03:00** cron запускает
`/usr/local/bin/nvgso-restore-test.sh`:

- берёт последний дамп;
- восстанавливает его в отдельную БД `nvgso_wp_restore`;
- проверяет количество таблиц, записей и пользователей;
- удаляет тестовую БД;
- пишет результат в `/var/log/nvgso-restore-test.log`.

Ручной запуск:

```bash
sudo /usr/local/bin/nvgso-restore-test.sh
sudo tail -1 /var/log/nvgso-restore-test.log
```

### 6.4. Восстановление вручную

```bash
# БД (перезаписывает текущую!)
gunzip -c /var/backups/nvgso/db/ФАЙЛ.sql.gz | sudo mariadb nvgso_wp

# Файлы
sudo rsync -a --delete /var/backups/nvgso/uploads/ \
  /var/www/nvgso/wp-content/uploads/
sudo chown -R www-data:www-data /var/www/nvgso/wp-content/uploads
```

Перед восстановлением сделайте свежий дамп текущего состояния.

### 6.5. UpdraftPlus

Дополнительно настройте UpdraftPlus на собственное внешнее хранилище:
**Настройки → UpdraftPlus → Настройки**, расписание и удалённое хранилище.

### Частые проблемы

| Симптом | Причина | Решение |
|---|---|---|
| 502 Bad Gateway | PHP-FPM не работает | `sudo systemctl restart php8.3-fpm`; проверить сокет |
| 500 | ошибка PHP/плагина | смотреть `nginx.error.log`; включить `WP_DEBUG` |
| Ошибка соединения с БД | MariaDB не запущена | `sudo systemctl restart mariadb`; `wp db check` |
| 404 на внутренних страницах | сломаны ЧПУ | `wp rewrite flush` |
| 403 на всех страницах | неверные права | `sudo chown -R www-data:www-data /var/www/nvgso` |
| 403 на `.php` в uploads | так и должно быть | защита |
| Сайт редиректит на старый IP | изменился адрес VM | раздел 11 |
| 2FA не принимает код | неверное время на телефоне / код использован | синхронизировать время, использовать резервный код |
| Нет баннера cookie | согласие уже сохранено | «Сбросить моё согласие» на странице журнала |
| Не видно изменений | кэш | `wp_cache_clear_cache()` |

## 9. Домен и HTTPS

Домен `nvgso.ru` привязан к `46.149.228.111`. HTTPS включён:

- сертификат Let's Encrypt для `nvgso.ru` и `www.nvgso.ru`;
- файлы: `/etc/letsencrypt/live/nvgso.ru/fullchain.pem` и `privkey.pem`;
- HTTP автоматически перенаправляется на `https://nvgso.ru` (301);
- `www.nvgso.ru` перенаправляется на `https://nvgso.ru`;
- включён HSTS (`max-age=15552000; includeSubDomains`);
- продление — `certbot.timer`, после продления Nginx перезагружается
  хуком `/etc/letsencrypt/renewal-hooks/deploy/reload-nginx.sh`.

Проверка:

```bash
curl -I https://nvgso.ru/
curl -I http://nvgso.ru/          # ожидается 301
curl -I https://www.nvgso.ru/     # ожидается 301 на nvgso.ru
sudo certbot renew --dry-run
```

Сертификат продлевается автоматически. Если DNS или IP меняются,
сначала обновите A-записи, затем проверьте `certbot renew --dry-run`.

## 10. Если изменился IP виртуальной машины

```bash

NEW_IP=10.0.2.20   # подставьте свой

  'https://nvgso.ru' "http://$NEW_IP" --all-tables --precise
sudo -u www-data wp --path=/var/www/nvgso eval 'wp_cache_clear_cache();'
```

## 14. Что осталось сделать

1. **Заменить демо-данные**: телефоны `00-00-00`, ФИО `[ФИО]`, адреса
   и тексты, унаследованные от прототипа.
2. **Утвердить юридические тексты** (ПДн, политика компании, cookie).
3. **Наполнить контент реальными материалами**: новости, документы,
   фотографии, командование.
4. **Настроить NAS** для внешней копии бэкапов (раздел 6.2) и SMTP
   для писем (раздел 3.5).
5. **Привязать домен и включить HTTPS** (раздел 9).
6. **Включить 2FA редакторам**, ограничить `/wp-admin` по IP.
7. **Проверить cookie-баннер** с юристом и, при необходимости,
   подключить аналитику через `data-consent="analytics"`.
8. **Проверить восстановление** из NAS-копии, а не только из локальной.
9. **Проверить вёрстку** на мобильных, в 200% масштабе, с клавиатуры
   и скринридером.
